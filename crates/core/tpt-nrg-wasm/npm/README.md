# tpt-nrg-wasm

Power-systems analysis in the browser and at the edge, compiled to
WebAssembly from the [TPT Energy](https://github.com/tpt-solutions/tpt-energy)
Rust workspace.

Every export is JSON in / JSON out, and every failure is a typed
`{ kind, message }` object, so a JavaScript caller can branch on the failure
without parsing message text.

## Install

```sh
npm install tpt-nrg-wasm
```

## Use

The package is built with `wasm-pack --target web`, so the module has to be
initialised before the exports are called:

```js
import init, { wasm_run_powerflow_json, wasm_visualize_json } from "tpt-nrg-wasm";

await init();                       // fetches and instantiates the .wasm module

const ieee14 = await fetch("/ieee14.json").then((r) => r.text());
const result = wasm_run_powerflow_json(ieee14);
console.log("converged:", result.converged, "losses:", result.losses_mw, "MW");

const svg = wasm_visualize_json(JSON.stringify({ system: ieee14 }));
document.querySelector("#diagram").innerHTML = svg;
```

A bundler (Vite, webpack, Rollup) inlines the `.wasm` for you; see the
[browser playground](https://github.com/tpt-solutions/tpt-energy/tree/master/playground)
in the repository for a complete example that loads an IEEE test case and
draws the voltage profile.

## API

| Export                              | Returns                                   |
|-------------------------------------|-------------------------------------------|
| `wasm_run_powerflow_json(input)`     | power-flow result object                  |
| `wasm_validate_system_json(input)`   | `undefined`, or throws `{kind, message}`  |
| `wasm_economic_dispatch_json(req)`   | dispatch result, as a JSON **string**     |
| `wasm_unit_commitment_json(req)`     | commitment result, as a JSON **string**   |
| `wasm_lcoe_json(req)`                | LCOE result, as a JSON **string**         |
| `wasm_carbon_intensity_json(input)`  | carbon intensity, as a JSON **string**    |
| `wasm_visualize_json(req)`           | an SVG single-line diagram as a string    |
| `wasm_microgrid_step_json(...)`      | one control step, as a JSON **string**    |
| `WasmMicrogridController`            | stateful microgrid control loop           |

The power flow is the one export with a typed result object, because it is the
one a UI renders field by field. The rest mirror the Rust API, which is
JSON-in/JSON-out, so they return a string: `JSON.parse` it.

```js
const dispatch = JSON.parse(
  wasm_economic_dispatch_json(JSON.stringify({ system: caseJson, load_mw: 100 })),
);
console.log(dispatch.generator_outputs_mw, dispatch.marginal_cost_dollar_per_mwh);
```

`WasmErrorKind` is one of `json`, `validation`, `non_convergence`,
`infeasible`, `control`, `serialization`. These slugs are part of the public
API and do not change within a major version.

TypeScript declarations are generated by `wasm-pack`; a copy is checked in at
[`tpt_nrg_wasm.d.ts`](./tpt_nrg_wasm.d.ts) and CI fails if it drifts from a
fresh build.
