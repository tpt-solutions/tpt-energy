# Building for the browser

This page walks through setting up `wasm32-unknown-unknown` and
building `tpt-nrg-wasm` for browser / edge consumption.

> **Note:** this requires the `wasm32-unknown-unknown` target, which
> must be installed on the build machine via `rustup`. CI workflows
> that build for the web run inside a container that has the target
> pre-installed.

## One-time setup

```bash
rustup target add wasm32-unknown-unknown
cargo install wasm-pack
```

## Build

From the workspace root:

```bash
wasm-pack build crates/core/tpt-nrg-wasm \
    --target web \
    --features wasm \
    --release \
    --out-dir pkg
```

The output lands in `pkg/`:

- `pkg/tpt_nrg_wasm_bg.wasm` — the compiled WASM module
- `pkg/tpt_nrg_wasm.js` — JS glue generated by wasm-bindgen
- `pkg/tpt_nrg_wasm.d.ts` — TypeScript type declarations
- `pkg/package.json` — npm package metadata

## Consume in a JavaScript project

```bash
npm install ./pkg
```

```js
import init, { wasm_run_powerflow_json, WasmMicrogridController } from "tpt-nrg-wasm";

await init(); // load the .wasm file
const ieee14 = await fetch("/ieee14.json").then(r => r.text());
const result = wasm_run_powerflow_json(ieee14);
console.log("converged:", result.converged, "losses:", result.losses_mw, "MW");

const ctrl = new WasmMicrogridController('{"assets":[],"grid_connected":true}');
const actions = ctrl.step("{}");
console.log("control actions:", actions);
```

## Bundler integration

For a `vite` / `trunk` / `webpack` setup, import the package and the
bundler will inline the WASM module:

```bash
cargo install trunk
trunk serve examples/wasm-demo
```

A complete `examples/wasm-demo/` browser app is tracked for a later
release — it will live in a sibling repository or in `examples/`
once the toolchain is set up in CI.

## Edge / bare-metal

For embedded targets (`wasm32-unknown-unknown` with `+no_std`),
restrict the dependency tree further:

```bash
wasm-pack build crates/core/tpt-nrg-wasm \
    --target bare \
    --features wasm \
    --release
```

This strips the JS glue and produces a freestanding `.wasm` suitable
for use inside a microkernel hypervisor.
