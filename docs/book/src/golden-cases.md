# Golden-case gallery

The workspace ships reference cases with committed expected results. They are
what the test suite compares against, and they are the quickest way to see
whether an installation behaves: every command below is a single line and
prints numbers you can check against the table.

The fixtures live in `test-data/` and are regenerated by the
`generate-ieee-goldens`, `generate-solar-goldens`, and `generate-wind-goldens`
binaries in the `examples/` sub-workspace. The `golden-drift` CI job fails if a
regeneration changes a committed value, so the numbers below cannot rot
silently.

## Power flow

| Case | Command | Result |
|------|---------|--------|
| IEEE 14-bus | `tpt-nrg run --system test-data/ieee/ieee14.json` | 14 buses, 7 iterations, 3.771 MW losses, 1.0185-1.0900 pu |
| IEEE 30-bus | `tpt-nrg run --system test-data/ieee/ieee30.json` | 30 buses, 6 iterations, 15.594 MW losses, 0.9770-1.0820 pu |
| IEEE 57-bus | `tpt-nrg run --system test-data/ieee/ieee57.json` | 57 buses, 5 iterations, 27.864 MW losses, 0.9359-1.0598 pu |

Machine-readable, for a script:

```sh
tpt-nrg run --system test-data/ieee/ieee14.json --format json | jq .total_losses_mw
```

A linear DC solution, for a first look at a large case:

```sh
tpt-nrg run --system test-data/ieee/ieee57.json --method dc
```

Fixture: `test-data/golden/powerflow/ieee-{14,30,57}-bus.json`.

## Format interoperability

Every bundled case round-trips through every writer, and the diff mode is how
you check that:

```sh
tpt-nrg convert test-data/ieee/ieee14.json --to matpower -o /tmp/case.m
tpt-nrg convert /tmp/case.m --round-trip
```

MATPOWER cannot carry bus names, so that round trip reports exactly the
`name` fields as removed and nothing else. `--round-trip` on the native JSON is
lossless and prints `no differences`:

```sh
tpt-nrg convert test-data/ieee/ieee14.json --round-trip
```

Cross-format comparison of two different cases:

```sh
tpt-nrg convert test-data/ieee/ieee14.json --diff test-data/ieee/ieee30.json
```

That exits `1` and lists the first differences by path, for example
`branches[id=1].rating_mva: 200.0 -> 130.0`.

## Dispatch and commitment

| Study | Command | Fixture |
|-------|---------|---------|
| Economic dispatch | `tpt-nrg run --system <case with cost curves> --dispatch 100` | `test-data/golden/dispatch/economic-dispatch-5gen.json` |
| Unit commitment | `tpt-nrg run --system <case with cost curves> --commit` | `test-data/golden/dispatch/unit-commitment-24hr.json` |

Both need a merit order: a case whose generators have no `cost_curve` cannot be
dispatched, and the CLI says so rather than inventing an order. The IEEE cases
in `test-data/ieee/` therefore cover the power flow, fault, and interop paths
but not the dispatch ones.

## Reproducing the fixtures

```sh
cargo run --manifest-path examples/Cargo.toml --bin generate-ieee-goldens
cargo run --manifest-path examples/Cargo.toml --bin generate-solar-goldens
cargo run --manifest-path examples/Cargo.toml --bin generate-wind-goldens
git diff --exit-code test-data   # non-zero means a fixture drifted
```

Generators round emitted values to 9 decimals so that libm differences between
platforms cannot produce false positives.
